# CLAUDE.md

Инструкции для работы в этом репозитории.

## Что это

Офлайновое PWA: персональный календарь на каждый день. Открыл иконку на
телефоне — сразу виден сегодняшний день по строкам активностей, свайп листает
соседние дни. Данные приходят из Google Sheets через `.xlsx` и конвертер.

Клиентов может быть много, у каждого своя ссылка:
https://yaroslavmalygin.github.io/bc/NN/ — например `/bc/01/`.
Диапазон и набор строк — **свойство клиента**, а не проекта, и лежат в
`clients/NN/client.json`. У клиента 01 это 2026-08-01 … 2027-07-31,
365 дней и 12 месяцев.

Раскладка каталогов:

| Каталог | Что это |
|---|---|
| `app/` | исходник оболочки, единственное место, где её правят |
| `clients/NN/` | `client.json` (коммитится) и `calendar.xlsx` (под gitignore) |
| `docs/NN/` | **сгенерированная** сборка, её раздаёт GitHub Pages |

`docs/NN/` править руками нельзя: пересборка снесёт правку. Правится `app/`,
дальше `python tools/build_client.py --all`.

Статика без сборки: ни npm-бандла, ни фреймворка. Playwright в
`devDependencies` нужен только тестам.

## Что нельзя трогать никогда

Ссылка выдана, иконка стоит на телефоне. В репозитории обратимо всё — кроме
адреса. Для браузера адрес **и есть** приложение: сменится он, и иконка
поведёт в никуда, а кэш оболочки с IndexedDB останутся у мёртвого адреса.
Пушем это не чинится, только просьбой к клиенту ставить заново — то есть
потерей всего офлайнового состояния.

| Заморожено | Почему |
|---|---|
| имя репозитория `bc` | входит в адрес `/bc/NN/` |
| номер клиента = имя папки, `01` | тоже входит в адрес; другой номер — для браузера другое приложение |
| источник Pages: ветка `main`, каталог `/docs` | переключение снимает сайт с адреса |
| `SITE_BASE = "/bc/"` в `tools/calendar_config.py` | отсюда пишется абсолютный `id` в манифесте; разойдётся с адресом — установленное PWA перестанет узнавать себя |
| отсутствие своего домена | решено сознательно: переезд стоит офлайн-данных всем установленным копиям |

Ничего из этого не ловится ни тестами, ни pre-push: это не поведение кода, а
идентичность приложения. Единственная страховка — не делать.

Всё остальное — сломанная оболочка, кривые данные, забытая пересборка —
откатывается коммитом и доезжает до клиента на первом же онлайн-открытии:
`sw.js` объявляет `skipWaiting` и `clients.claim`, чистки кэша руками не
требуется.

## Команды

```bash
# один раз на клон: включить проверки перед публикацией
git config core.hooksPath .githooks

# данные и сборка
python tools/make_reference_xlsx.py --mode demo --client clients/01/client.json \
       --out .tmp/reference-demo.xlsx              # эталонная книга (вкладка на месяц)
python tools/make_reference_xlsx.py --layout stacked ...   # стопка блоков на листе
python tools/xlsx_to_calendar_json.py 01 --report-colors  # что за заливки в файле
python tools/xlsx_to_calendar_json.py 01                  # clients/01/ → docs/01/
python tools/build_client.py 01                    # app/ → docs/01/
python tools/build_client.py --all                 # пересобрать оболочку всем

# тесты — прогонять все перед тем, как назвать работу законченной
python tests/test_client_config.py    # 20 проверок конфига клиента
python tests/test_build_client.py     # 6 проверок генератора сборок
python tests/test_converter.py        # 39 проверок: сломанные книги, обе
                                      # раскладки, пути и опоры луны
node   tests/test_dates.mjs --all-zones  # 77 проверок × 11 часовых поясов
node   tests/test_client_id.mjs       # 7 проверок вывода идентификатора
node   tests/test_app.mjs             # 69 проверок в настоящем браузере
node   tests/test_clients.mjs         # изоляция двух клиентов в одном браузере
node   tests/test_live.mjs            # 17 проверок опубликованного сайта

# локальный запуск
python -m http.server 8000 --directory docs   # затем http://127.0.0.1:8000/01/
```

Скриншоты браузерных тестов складываются в `.tmp/screens/`.

### Хук перед публикацией

Push в `main` — это и есть выкладка клиенту: Pages раздаёт `docs/` сразу, а
промежуточной среды нет. Поэтому `.githooks/pre-push` (~75 секунд) гоняет
все тесты, кроме `test_live.mjs`, и добавляет две проверки, которых у тестов
нет в принципе:

- **`docs/` собран из текущего `app/`.** Браузерные тесты собирают фикстуру
  в `.tmp` и в `docs/` не заглядывают, так что забытый `build_client.py`
  даёт зелёный прогон и публикацию прошлой оболочки. Хук сверяет настоящим
  генератором, собирая во временный корень через `--root`.
- **`APP_CACHE_VERSION` поднят, если `app/` менялся** между тем, что уже на
  сервере, и тем, что пушится. Без подъёма установленный клиент останется на
  старой оболочке молча и неограниченно долго.

Обе проверки проходят мимо тестов полностью: прогон остаётся зелёным, а
клиент получает не то. Обойти хук осознанно — `git push --no-verify`.

Сравнение побайтное, поэтому переводы строк обязаны быть предсказуемы:
`.gitattributes` держит LF везде, а генераторы (`build_client.py`,
`xlsx_to_calendar_json.py`) пишут файлы с явным `newline="\n"`. Без этого
Python на Windows кладёт CRLF, гит хранит LF, и после любого `checkout`
сборка переставала бы совпадать сама с собой — хук требовал бы пересборки
на ровном месте, а хук, который врёт, обходят и защиты больше нет.

## Инварианты, которые легко сломать не заметив

Каждый пункт — не стилистика, а поведение, которое уже ломалось или было
бы неотличимо от рабочего.

### Идентификатор клиента выводится из адреса скрипта

Cache Storage, IndexedDB и localStorage делятся по **origin**, а не по пути.
Все календари живут на `yaroslavmalygin.github.io`, то есть в одном
хранилище на всех. Без идентификатора два календаря на одном телефоне писали
бы в одну базу, а чистка старых кэшей у одного сносила бы офлайн-оболочку
другого — и увидеть это можно было бы только в самолёте.

`app/client-id.js` берёт последний сегмент адреса **своего модуля**, не
документа: от документа идентификатор поехал бы при другом имени входной
страницы. Ничего не подставляется при сборке — папка и идентификатор
совпадают по построению.

Отсюда три следствия:

- имя базы — `business-calendar-<id>`;
- префикс кэша — `calendar-<id>-shell-`, и чистка в `activate` фильтрует
  **по своему** префиксу; общий `calendar-shell-` снёс бы оболочку соседей;
- `fetch` ищет в своём кэше (`cache.match`), а не глобально
  (`caches.match`) — глобальный поиск мог бы отдать файл другого клиента.

`id` в манифесте пишет генератор, и он **абсолютный** (`/bc/NN/`):
относительный резолвится от origin, и у всех клиентов совпал бы. В
`app/manifest.webmanifest` поля `id` нет намеренно.

Номер клиента после выдачи ссылки не меняют: для браузера это другое
приложение, и офлайн-данные с иконкой останутся у старого адреса.

Проверяется в `tests/test_client_id.mjs` и `tests/test_clients.mjs`.

### Диапазон и строки живут в конфиге клиента

`clients/NN/client.json` описывает то, что различается: диапазон, строки,
дополнительные символы. `tools/calendar_config.py` остался конфигом
**астролога** — палитры, раскладка блока, каталог символов.

Число месяцев и дней **вычисляется** из диапазона, а не задаётся рядом с ним.
Тремя независимыми константами их легко рассогласовать, и рассогласование
выглядело бы как рабочий календарь не на тот год.

Диапазон всегда покрывает целые месяцы: начало — первое число, конец —
последний день месяца. Половина месяца означала бы блок, часть которого не
с чем сверить.

Расхождение таблицы с конфигом — остановка, а не догадка: и когда строк в
конфиге больше, чем в книге, и когда меньше.

### Оболочка и данные разделены

`build_client.py` копирует `app/` целиком в `docs/NN/` и **не трогает**
`docs/NN/data/`. Данные пишет только конвертер, а исходный `.xlsx` лежит под
`.gitignore` — на чистом клоне его нет, и затирающая пересборка стёрла бы
календари всех клиентов разом.

Прошлая сборка сносится целиком: иначе файл, удалённый из `app/`, остался бы
у клиента навсегда и продолжал раздаваться.

Копия на каждого клиента, а не общий код: общий сэкономил бы место, но
правка тихо меняла бы поведение у всех без пересборки и без прогона тестов
на их данных.

### Даты — только через `app/dates.js`

Никакой арифметики по датам снаружи этого модуля. Запрещено везде:

- `new Date("2026-08-12")` — строка `YYYY-MM-DD` парсится как UTC-полночь,
  и западнее Гринвича даёт предыдущий день;
- `toISOString()` для ключа дня — переводит в UTC, часть суток отдаёт
  соседнюю дату;
- `+ 86400000` для перехода к следующему дню — на переводе часов в сутках
  23 или 25 часов.

Ключ дня — строка `YYYY-MM-DD` в **локальном** календаре устройства.
«Сегодня» определяется по дате телефона; даты из таблицы между поясами не
пересчитываются.

### `calendar.json` не проходит через service worker

`app/sw.js` кэширует **только оболочку**. Попади данные под его обработчик,
воркер сохранил бы сетевой ответ раньше, чем приложение его провалидирует, —
и повреждённый JSON осел бы в кэше как рабочий, а вся защита last-known-good
стала бы декоративной.

Порядок в `app/store.js` менять нельзя:
`получить → распарсить → провалидировать → previous = current → current = new`.
При ошибке на любом шаге хранилище не меняется вообще.

Тест `test_live.mjs` прямо проверяет, что `calendar.json` в кэше воркера нет.

### Раскладок книги две, и обе настоящие

Файл астролога устроен так: лист «Легенда» и дальше **вкладка на каждый
месяц**. Раньше конвертер знал только стопку блоков на одном листе
«Календарь» — её по-прежнему умеет читать генератор эталона и старые книги.

Внутри блока раскладки совпадают до строки. Различается ровно одно: где
стоит `STATUS: READY`. В стопке — в строке заголовка месяца, во вкладке —
строкой выше, над блоком. Поэтому статус ищется **в пределах блока**, а не
по фиксированному смещению: окно считается в `find_blocks_on_sheet` и тянется
от конца предыдущего блока до конца своего.

Имя вкладки не значит ничего. Месяц берётся из заголовка в колонке B: в
настоящем файле вкладка называется «Февраля 2027» при заголовке
`ФЕВРАЛЬ 2027`, и верен заголовок. Подстраховка не в имени листа, а в
`validate_range`: набор месяцев обязан совпасть с конфигом клиента.

Раскладка определяется структурно (`collect_blocks`):

- лист с именем из `CALENDAR_SHEET_CANDIDATES` → стопка блоков;
- иначе два и больше листов, на каждом ровно по одному блоку → вкладки;
- блоки вперемешку по листам → остановка, догадка тут дороже ошибки.

Раскладка не влияет на данные вообще: тест сравнивает `dataHash` книг,
собранных обеими, и он обязан совпадать до байта.

### Числа месяца могут прийти как `1.0`

Выгрузка Google Sheets отдаёт числа float. Наивный `int(str(value))` на
такой ячейке падает, и блок перестаёт опознаваться: заголовок есть, а
нумерации под ним «нет». Разбор чисел — только через `as_day_number`.

### Белая заливка = пустая ячейка

Google Sheets красит белым и все дни без фазы, и запас колонок за таблицей.
Поэтому `FFFFFF` описан в `PALETTE_DATES` как `plain`, а `check_nothing_beyond`
через `is_blank_fill` не считает белое остатком копии месяца. Цветной остаток
справа ловится по-прежнему — на нём и держится вся проверка.

В `PALETTE_ACTIVITY` белого нет намеренно: в зоне активностей цвет означает
благоприятность, и белая ячейка там — вопрос к таблице, а не к конвертеру.

### Строки таблицы опознаются по позиции, а не по подписи

В исходной таблице подписи одной строки различаются от месяца к месяцу:
«Важ перег, выступления» против «Важ перег, выступ.», «Фин, перечисления,
инвест.» против «Финансы,переч, инв.». Сопоставление по тексту развалится на
втором же месяце. Строка опознаётся по порядковому номеру в блоке, а подписи
и `id` берутся из `rows` в `clients/NN/client.json` — порядок там обязан
совпадать с порядком строк в таблице.

### Две палитры, по одной на зону

Строка дат и строки активностей живут в разных цветовых мирах: бежевый с
синим против зелёного, жёлтого и красного. Один общий словарь заставит
стража неизвестного цвета спотыкаться о бежевую шапку выходных.

Выходные считаются **из даты**, а не из заливки.

### `dataHash` и `APP_CACHE_VERSION` — разное

| Что изменилось | Что делать |
|---|---|
| только `docs/NN/data/calendar.json` | ничего, версия считается сама |
| разметка, скрипты, стили, шрифт, иконки, манифест, сам `sw.js` | поднять `APP_CACHE_VERSION` в `app/sw.js`, затем `python tools/build_client.py --all` |

`dataHash` считается по канонической сериализации без полей `dataHash` и
`generatedAt` — иначе круговая зависимость и смена версии при холостом
перегоне.

### `robots.txt` разрешает обход намеренно

Из поиска страница выпадает мета-тегом `noindex` в `index.html`. Поставить
`Disallow: /` — значит помешать краулеру этот тег прочитать, и URL всё равно
сможет попасть в индекс по внешней ссылке. Результат ровно обратный
задуманному.

### Конвертер обязан падать, а не догадываться

Приложение офлайновое: тихо испорченные данные никто не заметит месяцами.
Любое расхождение — остановка с указанием месяца и ячейки. Добавляя проверку,
пиши сообщение так, чтобы по нему было понятно, что именно править в таблице.

### Один экран, portrait

Весь день обязан помещаться без вертикального скролла. Каркас — флекс на
`100dvh` (не `vh`), восемь строк делят остаток высоты через `flex: 1 1 0`.
Всё, что могло бы толкать страницу вниз, живёт в шторках. Если не помещается,
включается компактный режим — но информация не обрезается.

Landscape не поддерживается намеренно: показывается просьба повернуть телефон.

## Заполненность месяцев

Определяется маркером `STATUS: READY` в колонке **A** в пределах блока
месяца: в стопке блоков — в строке заголовка, во вкладке на месяц — строкой
выше. Контракт строгий:

- ровно один статус на блок, два и больше — ошибка;
- регистр не важен, пробели срезаются;
- любое другое значение в колонке A внутри блока — ошибка, чтобы опечатка
  `STATUS: REDY` не превращалась молча в «месяц не заполнен»;
- статуса нет — месяц считается плейсхолдером, это не ошибка.

Незаполненный месяц **никогда** не показывает строки другого месяца: вместо
них сообщение «Данные на этот месяц ещё не заполнены».

## Фазы луны

Источник — синие и голубые заливки в строке дат. Освещённость между опорами
интерполируется, но выдумывать фазу нельзя: при разрыве больше 20 дней или на
краю диапазона, где опоры с одной стороны нет, показывается нейтральный
пунктирный диск и «Нет данных о фазе». Экстраполяция запрещена.

Типы обязаны чередоваться. Два одинаковых подряд — ошибка конвертера.

### Края диапазона закрывают опоры из конфига

Таблица астролога кончается вместе с диапазоном, поэтому первым и последним
двум неделям календаря не на что опереться с одной стороны — до 25 дней года
без фазы. Закрывается полем `moonAnchors` в `clients/NN/client.json`: две
даты снаружи диапазона, названные астрологом.

Считать их астрономически нельзя. Средняя синодическая модель промахивается
на сутки, а у края это меняет смысл: фаза либо попадает в таблицу, либо
выпадает наружу и становится опорой. Ошибка в опоре тихо перекашивает
освещённость на две недели вперёд.

Опора обязана быть **ближайшей** фазой снаружи. Спрятанная между ней и краем
таблицы фаза заставила бы интерполяцию пройти сквозь себя и нарисовать диск
задом наперёд, поэтому конвертер проверяет и чередование типов, и расстояние
до соседней фазы (не больше `MOON_GAP_BREAK`).

Фаза ровно в последний день диапазона лежит **внутри** — её размечает
таблица, а опорой становится следующая за ней.

## Стиль

- Комментарии и текст интерфейса — по-русски. Комментарий объясняет **почему**
  так сделано, а не пересказывает код.
- Кнопки от 44 × 44, иконки — инлайновый SVG, не эмодзи.
- Обе темы через `prefers-color-scheme`; токены на `:root`.
- Никаких новых зависимостей в рантайме: приложение должно оставаться
  статикой без сборки.

Опоры луны названы астрологом: `2026-07-29` полнолуние до диапазона и

В файле есть особенности, которые конвертер разбирает сам, но о которых
стоит знать: холостой ход луны набран строчной `х` (регистр поднимается
только там, где строчная форма не занята — `У` и `у` разные символы), числа
месяца лежат как `1.0`, а справа от каждого месяца идёт колонка с белой
заливкой. Всё три — норма выгрузки Google Sheets, не поломка.

Шапка листа «Легенда» осталась от прежнего плана и гласит «Август 2026 -
Август 2027». На разбор не влияет, но при случае астрологу стоит сказать.
