# Заведение нового клиента

SOP на случай, когда астролог привёл нового заказчика. Результат — отдельная
ссылка вида `https://yaroslavmalygin.github.io/bc/NN/`, которую можно поставить
на домашний экран.

Копировать проект не нужно: оболочка одна на всех, различия клиента живут
в `clients/NN/client.json`.

## Что понадобится

- Свободный номер клиента (`clients/` показывает занятые)
- Ответы на четыре вопроса из шага 2
- Таблица клиента в Google Sheets, выгруженная в `.xlsx`

---

## 1. Выбрать номер

```bash
ls clients/
```

Номер — две цифры, по порядку: `01`, `02`, `03`. Он же станет папкой в адресе
и идентификатором хранилища на устройстве, поэтому менять его после выдачи
ссылки нельзя: у клиента отвалятся офлайн-данные и установленная иконка.

## 2. Интервью

Четыре вещи, которые различаются от клиента к клиенту:

1. **Диапазон.** С какого месяца считается год и по какой. Всегда целые
   месяцы: начало — первое число, конец — последний день месяца.
2. **Строки.** Сколько их и что в них. Порядок в конфиге обязан совпадать
   с порядком строк в таблице: строки опознаются по позиции, а не по подписи.
3. **Подписи.** Полная (`label`, видна в подробностях) и короткая (`short`,
   видна в строке дня).
4. **Новые буквы.** Если у клиента появился символ, которого нет в общем
   каталоге (`KNOWN_MARKS` в `tools/calendar_config.py`), его расшифровка
   идёт в `extraMarks`. Переопределять буквы каталога нельзя — конвертер
   остановится.

## 3. Завести конфиг

```bash
mkdir -p clients/NN
```

`clients/NN/client.json`:

```json
{
  "range": { "start": "2026-09-01", "end": "2027-09-30" },
  "rows": [
    { "id": "negotiations", "label": "Важные переговоры и выступления", "short": "Переговоры" },
    { "id": "finance", "label": "Финансы, перечисления, инвестиции", "short": "Финансы" }
  ],
  "extraMarks": {
    "П": "Пластика: восстановление пройдёт быстрее."
  }
}
```

`id` строки — латиницей, без пробелов, уникален внутри клиента. Он попадает
в `calendar.json` и в разметку, поэтому менять его позже — значит потерять
привязку сохранённых данных.

Число месяцев и дней **не задаётся**: оно вычисляется из диапазона. Три
независимые константы легко рассогласовать, а рассогласование выглядело бы
как рабочий календарь не на тот год.

## 4. Принять таблицу

В Google Sheets: **File → Download → Microsoft Excel (.xlsx)**.
Положить в `clients/NN/calendar.xlsx`.

> Только `.xlsx`. CSV, PDF и любой текстовый экспорт теряют заливку ячеек,
> а в ней половина смысла календаря — благоприятность дня и фазы луны.

Файл под `.gitignore`: это заметки астролога до вычистки стоп-слов, в
публичный репозиторий им нельзя. Сам `client.json` рядом коммитится — имён
в нём нет.

## 5. Посмотреть, какие цвета в файле

```bash
python tools/xlsx_to_calendar_json.py \
  --xlsx clients/NN/calendar.xlsx \
  --client clients/NN/client.json \
  --report-colors
```

Что проверить — см. шаг 2 в [update_calendar_data.md](update_calendar_data.md):
нет строк «НЕ ОПИСАН В ПАЛИТРЕ», вид заливки `rgb`, условного форматирования
на данных нет.

## 6. Холостой прогон в `.tmp`

Прежде чем писать в `docs/`, убедиться, что таблица вообще разбирается:

```bash
python tools/xlsx_to_calendar_json.py \
  --xlsx clients/NN/calendar.xlsx \
  --client clients/NN/client.json \
  --out .tmp/probe-NN.json
```

Здесь же выясняется, сошлись ли конфиг и таблица: число месяцев, число строк,
неизвестные буквы. Правится **таблица или конфиг**, а не конвертер.

## 7. Сверить символы с каталогом

Конвертер останавливается на любой букве, которой нет ни в `KNOWN_MARKS`,
ни в `extraMarks`. Решение принимается осознанно:

- буква встречается у всех клиентов → в `KNOWN_MARKS` и `MARK_TEXTS_FALLBACK`
  в `tools/calendar_config.py`;
- буква только у этого клиента → в `extraMarks` его конфига;
- буква — опечатка астролога → правится таблица.

## 8. Показать Яро заметки месяцев

Заметки уезжают в публичный репозиторий. Стоп-слова из `PRIVACY_STOPWORDS`
вырезаются автоматически, но список закрывает только известные имена.
Прочитать заметки глазами до публикации — обязательный шаг, а не формальность.

## 9. Собрать

```bash
python tools/build_client.py NN
python tools/xlsx_to_calendar_json.py \
  --xlsx clients/NN/calendar.xlsx \
  --client clients/NN/client.json \
  --out docs/NN/data/calendar.json
```

Порядок именно такой: генератор кладёт оболочку, конвертер — данные. Обратный
порядок ничего не сломает (генератор данные не трогает), но лишний раз
проверять это незачем.

Шлюз перед публикацией конвертер печатает сам. Пока в нём есть красное,
это демонстрационная сборка, а не финальный календарь.

## 10. Прогнать тесты

```bash
python tests/test_client_config.py
python tests/test_build_client.py
python tests/test_converter.py
node   tests/test_dates.mjs --all-zones
node   tests/test_client_id.mjs
node   tests/test_app.mjs
node   tests/test_clients.mjs
```

Все должны быть зелёными. `test_clients.mjs` проверяет то, что глазами не
видно: два календаря на одном телефоне не лезут в чужое хранилище.

## 11. Опубликовать

```bash
git add clients/NN/client.json docs/NN
git commit -m "Клиент NN"
git push
```

GitHub Pages подхватит изменения за минуту-две.

## 12. Проверить боевой адрес

```bash
node tests/test_live.mjs https://yaroslavmalygin.github.io/bc/NN/
```

Затем — руками, и это автоматика не заменяет: открыть адрес на настоящем
телефоне, поставить на домашний экран, включить авиарежим, убедиться, что
календарь открывается офлайн.

## 13. Передать ссылку

`https://yaroslavmalygin.github.io/bc/NN/` плюс короткая инструкция:
открыть в Safari или Chrome, «Поделиться» → «На экран Домой».

## Если конвертер остановился

Это норма, а не сбой. Приложение офлайновое: тихо испорченные данные никто не
заметит месяцами, поэтому конвертер обязан падать, а не догадываться.

В сообщении названы месяц и ячейка. Правится **таблица или конфиг клиента**,
не конвертер. Ослабить проверку, чтобы «прошло» — значит выпустить календарь,
про который никто не знает, где он врёт.

Типичные случаи:

| Сообщение | Что делать |
|---|---|
| «набор месяцев не совпадает» | диапазон в конфиге не тот, что в таблице |
| «не найдены подписи строк активностей» | в конфиге строк больше, чем в таблице |
| «нашлась ещё одна» | в конфиге строк меньше, чем в таблице |
| «неизвестный символ» | буква не в каталоге и не в `extraMarks` |
| «заливка … не описана в палитре» | новый оттенок, см. шаг 5 |
| «в колонке A найдено несколько статусов» | лишний `STATUS: READY` в блоке |

## Если правится сама оболочка

Оболочка копируется каждому клиенту целиком, поэтому правка `app/` доезжает
до клиентов только через пересборку:

```bash
# 1. поднять APP_CACHE_VERSION в app/sw.js
# 2. пересобрать всем
python tools/build_client.py --all
```

`--all` перекладывает оболочку и **не трогает** `docs/NN/data/`: данные пишет
только конвертер, а исходных `.xlsx` на чистом клоне может не быть вовсе.
